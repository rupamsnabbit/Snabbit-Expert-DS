Core component

MediaCapture

Every photo the app asks for — the uniform selfie, the check-in photo, Aadhaar front and back, the finished kitchen — through one component: a tile that holds the slot and a preview that guides the shot, talks her through it, and always offers a retake. She never has to know what a megabyte is.

Guides

Behaviour

Rules

  1. Selfies and check-in photos are camera-only. Documents offer Take photo (primary) and Choose from gallery (tertiary).
  2. Retake replaces; there is no delete. A tile is cleared only by the flow that owns it.
  3. Size and format are handled silently — compressed on device; she never sees MB, JPG or "too large".
  4. Permission is asked through the Permission sheet first (why, then the OS dialog); denied → EmptyState with Allow camera.
  5. One control: the shutter. Flash auto for documents, off for faces. No zoom, torch, filters or timers.
  6. Checking ≤ 3 s, then a result. After three fails, Call Help joins Retake.
  7. Instructions and results are spoken as they change; the network dropping mid-upload keeps the photo locally and shows Couldn't upload — try again.

What changes in Figma

  1. Document Upload Card → MediaCapture / Tile: State (Empty / Uploading / Done / Error / Review), Shape (Square / Wide). Hint → what to photograph; ✕ → Retake.
  2. Camera Preview → MediaCapture / Preview: Guide (Face / Document / Scene), Result (None / Checking / Success / Fail); overlays bound to bgSuccessSubtle / bgErrorSubtle; add the instruction bar and Retake / Call Help.
  3. Delete the Camera / Gallery Selection Pill; gallery is a tertiary Button on document previews only.
  4. Add SOS to every check-in preview frame.

Result: ~12 variants, and a camera that explains itself. Token proposals: overlay.result 60 %, sound.shutter.
