Core component

HeaderNav

Says where she is and how to get back. On Home it also holds the numbers she cares about all day, Saathi, and SOS — each as an icon with a label — and it keeps SOS in the same place on every in-job screen. It never holds a menu.

Six shapes

Variants

Title is always left-aligned beside the back button — Indic titles run long and a centred title truncates unpredictably. One trailing element at most: an IconButton from the allowed set, or a small labelled Button.

Root

Home cluster

The shipped header's idea is right: each action is a small disc plus a label pill, so SOS says "SOS" and Saathi says "Saathi" (P2). What changes: a fixed set and order — coins, red cards, Saathi, SOS — with SOS always rightmost; no bell, no Help duplicate, no ≡. Coins and red cards use the reward assets, never a red Tag. Notifications live in Profile. The greeting (Namaste, Radhika) moves into the content, where it has room in every language — the header left holds only the wordmark.

Behaviour

Scroll behaviour

The header never hides on scroll — persistent orientation matters more than 56 dp for someone who gets lost easily. A 1 dp borderSubtle line appears once content has scrolled under it. Scroll the mock.

What changes in Figma

  1. TopNav → HeaderNav: Variant (Default / Root / Home / Search / In-job / Transparent), booleans Subtitle, Trailing (None / IconButton / Button).
  2. Delete the (i) and ≡ variants. Title left-aligned everywhere.
  3. "Home navigation bar nav" → HeaderNav / Home: keep the disc + label-pill item as a HeaderAction sub-component; fix the set and order to coins · red cards · Saathi · SOS; delete the Help, bell and ≡ items.
  4. Trailing Call → Button instance (secondary brand S, icon + label).
  5. Search variant uses a TextField search instance.

Result: ~12 variants replacing 11 frames.
