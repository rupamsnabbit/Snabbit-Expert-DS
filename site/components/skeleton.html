Skeleton · Spinner

Loading that is visible, cheap and short. A Skeleton holds the shape of what is coming; a Spinner lives only inside a Button or a row. A Skeleton still there after three seconds is not loading, it is failing — and the screen says so.

Six shapes

Shapes

Grey bgTertiary shapes on the real layout, in the real positions, at the real sizes, with one shimmer crossing all of them in sync. Radii follow what they stand for.

Drawn once

Presets

Every list or card screen has a named preset. Header, tab bar, SOS and Banners are never skeletons — they render real, immediately. Reduced motion: shapes are static.

Try it

Live · the three-second rule

Skeleton at 0 ms, no fade-in. Content swaps in one frame when it arrives. At 3 s the Skeleton is replaced by an EmptyState — offline if there is no connection, otherwise error with Try again. Never a Skeleton older than 3 s.

Spinner

A 2.5 dp arc rotating 800 ms, inheriting its container's text colour. Inside a Button it replaces the label and the fill lightens; inline it sits at the trailing edge of a row whose text stays readable. Never centred on a screen, never over a scrim, never beside a Skeleton.

What changes in Figma

  1. Create Skeleton shapes (Line / Amount / Circle / Block / Row / Card) bound to bgTertiary, and the five presets: JobCard, ListRows, EarningsHead, Breakdown, Home.
  2. Create Spinner (Size 16 / 20; Place Button / Inline); replace the hand-drawn arcs in Loading States with the instance.
  3. Delete the Retrying… screen; the flow becomes Skeleton → EmptyState error.
  4. Add a loading frame to each list screen mock — loading exists only if it is drawn.

Result: ~13 variants. Token proposals: motion.shimmer 1200 ms, motion.spin 800 ms, timeout.skeleton 3000 ms (shared with EmptyState).
