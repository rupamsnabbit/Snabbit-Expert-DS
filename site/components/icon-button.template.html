Core component

IconButton

A button whose whole meaning is one Phosphor icon. With no label, it is allowed only for actions the expert already knows by shape and place. Everything else is a Button with a verb.

ProposedTier 1 · CoreSnabbitIconButtonSame axes as Button8 allowed icons
The constraint

Allowed icons

Because there is no text, the icon must already be universal. These eight, in these positions, are the whole allowed set. Adding one means a register entry, a test with five experts who have never seen it, and the same place on every screen.

  • Not allowed: dots-three (overflow menus are hierarchical navigation — the research says it fails), pencil, trash, anything feature-specific. Those get a labelled Button.
  • Content description is mandatory — the verb the labelled version would show: "Back", "Call customer", "Hear again".
Emphasis × meaning

Variants × tones

Same colour table as Button. Filled brand exists only as a floating map or camera control — a filled IconButton is never the screen's one next action, because that action needs a verb (P2).

Sizing

Sizes & badge

Button's sizes and radii, so the two sit flush in a row. A circle shape exists only for floating controls. The badge is information — count ≤ 9, else 9+ — never a second tap target.

Behaviour

States

As Button: pressed, focused, disabled, loading (spinner replaces the icon, taps ignored). No hold gesture — anything worth a hold needs a label.
