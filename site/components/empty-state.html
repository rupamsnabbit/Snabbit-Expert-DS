EmptyState

The screen with nothing to show still says three things: what is true, why or what happens next, and what she can do. One shape for nothing-yet, couldn't-load, offline and waiting — learned once, spoken every time it matters.

Four reasons for nothing

Kinds

Same anatomy every time: a pictogram (pink disc, magenta object, the dot carries the status), a title that says what is true, a body that says why or when, a speaker on anything she must recover from, and one way out. Waiting always has a time, never a spinner.

Inside a card

Section size

When only part of a screen is empty — today's jobs on Home, this week's referrals — the 64 dp pictogram, a BodyLg title and at most a tertiary Button sit inside the Card.

Try it

Live

Try again runs with the Button's own loading state. On a second failure the body gains Still not working — call Help and Call Help becomes primary. Never more than two automatic retries; the third is hers. Offline swaps to real content the moment the connection returns.

error · spoken once on appearance
Words

Copy rules

  1. Title = what is true, ≤ 40 chars, no exclamation, no Oops, no Something went wrong.
  2. Body = one or two sentences, ≤ 80 chars. For errors: reassure first (Your money is safe), then the cause if known, then stop. Never an error code, never server, never blame.
  3. Button = a verb: Try again, Go online, Call Help, Refer a friend. Never OK, never Contact support.
  4. Waiting always has a time — Ready by 10:00 pm, Usually 2 hours — or says who will tell her.
  5. Never a dead end: error and offline always have a way out; empty has one whenever an action exists, otherwise the body says what will happen instead.
  6. Error, offline and waiting are spoken once on appearance; the speaker replays.

What changes in Figma

  1. Create EmptyState: Kind (Empty / Error / Offline / Waiting), Size (Page / Section), booleans Speaker, Body, Button, SecondButton.
  2. Rebuild the ERRORS frames as error instances — search-document-✗ pictogram, Try again + Call Help; delete the red warning-circle glyph and the Retrying… spinner screen.
  3. Add the missing empty pictograms (calendar without a dot, and one per tab) to the Assets page.
  4. Add an empty instance to every list screen mock — the state exists only if it is drawn.

Result: ~10 variants, and the first drawn empty states in the app.
