# Build plan — the real prototype (voice in, voice out, on the phone)

Decided 2026-10-13 with the lead: **real voice, Hinglish, on his phone, all three lanes, easily switchable.**
Source of the screens: Figma V2 (`reads/figma-v2-read-2026-10-13.md`). Source of the behaviour: `FLOW.md` v3.
This is a project workspace artefact, like a walkthrough (`DECISIONS.md` 2026-09-29): it never redraws a
screen that Figma did not draw, it is never evidence for a spec, and it is not published.

## 1 · What it is

A single web page, opened in Chrome on the lead's Android phone, that **is** the flow: real screens built from the
tokens, real taps, Saathi speaking through the phone's Hindi voice, the phone's microphone listening, and the screen
branching on what was said. No hotspots, no videos of screens, no fake mic.

| Layer | Choice | Why |
| --- | --- | --- |
| Screens | HTML + CSS from `tokens/tokens.json` (generated `tokens.css`), Outfit, Phosphor SVG inline | Same source of truth as the site; every value is a `var(--…)`, lint-clean |
| Runtime | One `index.html` + `app.js` + `voice.js` + `data.js`, no framework, no build step | Opens from a URL, nothing to install on the phone |
| Voice out | `speechSynthesis`, voice `hi-IN` (Google हिन्दी on Android), rate 0.95 | Hinglish written in Latin + Devanagari mix is read naturally by the Hindi voice |
| Voice in | `webkitSpeechRecognition`, `lang = 'hi-IN'`, `interimResults = true`, `continuous = false` | Live transcript on F3 is the interim result; Hindi model handles Hinglish place names after a vocabulary pass |
| Parser | Rule-based, in `voice.js`: vocabulary → slots (place · time · friend · intent) | Deterministic; the demo must branch the same way twice |
| Serving | `serve.py` on the Mac → **HTTPS** URL on the phone (quick tunnel if `cloudflared` is present, else a self-signed cert + one tap on the warning) | Mic and TTS need a secure context |
| Switch | Hidden: long-press the status bar → sheet with lane · state · voice mode; also URL `?lane=T|HT|C&state=open|full&voice=real|script` | "Easily switchable" without a visible dev UI |

Folder: `projects/hood-shift-change/prototype/` — `index.html`, `app.js`, `voice.js`, `data.js`, `tokens.css`
(generated by `tools/tokens_to_css.py`, to be written), `serve.py`, `assets/` (Saathi, pictograms exported from
Figma V2 at 2×).

## 3 · The screens — what each one says, hears, and does

Every screen: Saathi **says** its line once on entry (skippable by tapping the orb), then **listens** for ≈6 s or until
silence. What she says lands in one of five responses (FLOW v3): **answer** the screen's question · **act here** (a
filter, a tick) · **open the sheet** · **say only** (voice answers, screen unchanged) · **new ask** (back to the guide
with the fields refilled). Two misses → "tap karke batao", mic stays on, nothing else changes. Every spoken option is
a tap target on the same screen (P4). The orb is one control: speaking / idle / listening / thinking.

## 4 · The parser (`voice.js`)

Input: the final transcript (Devanagari and Latin mixed). Steps: lower-case, strip punctuation, transliterate the
Devanagari digits and the ten common number words (एक…दस, ek…das) to digits, then match in this order:

| Slot / intent | Vocabulary (both scripts) | Example hits |
| --- | --- | --- |
| **affirm** | haan, haa, ha, theek, thik, ok, pakka, sahi, yes, lena hai, kar do, हाँ, ठीक, पक्का | "haan pakka" |
| **negate** | nahi, nahin, na, mat, rehne do, नहीं, रहने दो | "nahi" |
| **place** | hsr, bellandur, agara, kudlu, koramangala, marathahalli (+ Devanagari spellings; *sector n*, *nth main* as sub-hood) | "HSR Sector 9" |
| **same place** | yahin, yahi, wahi jagah, isi hood, यहीं | "yahin bas time badlo" |
| **time** | `(\d{1,2})\s*(se|to|-|से)\s*(\d{1,2})` → start/end; single `(\d{1,2}) baje` → start, keep her hours; subah/dopahar/shaam → part of day; `(\d) ghante` → hours filter | "subah 9 se 5", "7 baje se", "6 ghante" |
| **friend** | dost, saheli, saath, friend, id, expert id, a 5-digit number, a known name (anita) | "meri dost ki id 14586 hai" |
| **waitlist** | waitlist, wait, bata dena, khulne pe, jab khule, रुक | "khulne pe bata dena" |
| **leave** | hatao, hata do, chhodo, cancel, waitlist se nikalo | "waitlist hatao" |
| **back / home** | peeche, wapas, back · ghar, home | "peeche" |
| **more** | aur, aur dikhao, baaki, zyada | "aur dikhao" |
| **say-only questions** | kitna (paisa / milega / door), kab se, kaunsa | "kitna milega" |

Resolution per screen (the table in § 3): a slot the screen can answer → **answer**; a filter word → **act here**;
waitlist / leave → **sheet**; a question → **say only** (one line, numbers from `data.js`); a place or time the screen
cannot use → **new ask** (S1b with the fields refilled and re-read); nothing matched → miss counter.

Scripted mode: the same parser runs on a written transcript per screen (`data.js → script[lane][screen]`), typed in
on screen over 0.6 s like F3 does, so the demo looks identical when the room is loud.

## 5 · Build order

1. `tools/tokens_to_css.py` → `tokens.css`; `serve.py` (HTTPS + QR code in the terminal); `index.html` shell with the
   360 × 800 stage scaled to the phone, status bar, orb, switch sheet. **Prove on the phone: a tap makes Saathi say
   one line in Hindi, and the mic returns a Hinglish transcript.** Nothing else until this passes.
2. Shared spine: Entry → V → N1–N4 (fan slides as in Figma, 3 s each) → F3 live transcript → S1b read-back → L.
3. Lane HT open and full (the longest path, touches every component: option card, status card, radio list, sheets,
   per-lane confirm, done).
4. Lane T open and full (reuses everything; the confirm sheet gets its time-change variant).
5. Lane C (friend ask, keypad, confirm-her, R3 three states).
6. Parser hardening with ten recorded phrases per lane in the lead's own voice; say-only answers; two-miss fallback.
7. Switch sheet, URL params, scripted mode; a `README.md` in the folder with the one command and the QR code.

## 6 · Verification (run on the phone, say when it was not run)

- Each lane, open and full, end to end **by voice only**, hands off the screen; then the same **by tap only**.
- The five responses, one each, on H3: "Agara" (answer), "6 ghante" (act here), "khulne pe bata dena" (sheet),
  "kitna milega" (say only), "Marathahalli chahiye" while waitlisted (W3 line).
- Two misses → tap fallback, screen unchanged.
- Numbers: every ₹ and time on a screen traces to `data.js`; the confirm sheet's Now line equals Entry's line.
- Lint: `python3 site/lint.py` ignores the folder (prototype, not spec) — but `tokens.css` is generated, so no raw hex
  exists in the hand-written files; grep for `#[0-9a-f]{6}` in the folder returns nothing.
