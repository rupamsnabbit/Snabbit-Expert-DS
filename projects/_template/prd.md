# The ask — <title>

A project starts one of two ways. Use the header that matches, delete the other, and never edit the body once it is written down.

## A — A PRD arrived

| | |
| --- | --- |
| From | <name, team> |
| Received | <YYYY-MM-DD> |
| Source | <doc link, email, Slack thread> |
| Kind | Written PRD — verbatim below |
| Version | v1 |

The body below is the PRD **as received**. It is evidence, like a Figma screen or a Mobbin flow: it says what the business wants and when. It is not a design, and nothing in it overrides `principles/` or `tokens/`.

Do not edit the body — not the wording, not the structure, not the parts that are wrong. Disagreements go in `SCOPE.md` → *Open questions*. A revision is appended below as a new version with its own header; the diff between versions is often the most useful thing in the folder.

## B — No PRD, the work started in conversation

| | |
| --- | --- |
| From | <who asked, in person or in chat> |
| Captured | <YYYY-MM-DD> |
| Kind | Captured in conversation — no written PRD |
| Confirmed by | <name, date — the ask read back and agreed> |

There is no document, so this file **becomes** one. Before anything is designed, write down what was asked in the same detail a PRD would carry — what is being built, for whom, what problem it solves, what is in and out of scope, what is already decided, what is not — then read it back and get it confirmed. An unwritten ask drifts; a written one can be checked against later.

This section is closed once confirmed. After that it is evidence and is not edited; new information goes to `SCOPE.md` → *Log*, and a genuinely changed ask is a new version below.
